# Internationalization

**English** | [简体中文](i18n.zh-CN.md)

Copy lives in two layers. The frontend holds every interface string in locale JSON files
and picks the text for an error `code`; the backend only answers with that `code` plus a
fallback `message` localized by `services/i18n.rs`. Neither layer duplicates the other's
table, and no copy is kept in code comments.

## Languages

| Tag | Language | Status |
| --- | --- | --- |
| `en-US` | English | Supported, fallback |
| `zh-CN` | Simplified Chinese | Supported |
| `ja-JP` | Japanese | Reserved, arrives with T30 |

`services/i18n.rs` exposes `Language::{ZhCn, EnUs}`, `Language::DEFAULT` (`en-US`) and
`Language::ALL` for the settings list. The choice in force is persisted in `config.json` by
`config.rs` (T05).

## First launch

When `config.json` has no `language` value (missing, `null` or blank), `Config::open` reads
the operating system's preferred locale through [`sys-locale`](https://docs.rs/sys-locale/).
English locales such as `en-GB` map to `en-US`; Chinese locales such as `zh-Hans-CN` and
`zh-TW` map to the available Simplified Chinese translation, `zh-CN`. Matching ignores case
and accepts both BCP-47 tags and POSIX forms such as `zh_CN.UTF-8`.

If detection fails or the locale has no supported translation, the choice is `en-US`.
The resolved tag, including a fallback, is saved immediately when creating a new file.
For an existing configuration, saving is best effort and patches only `language`, preserving
relative database paths, unknown keys and all other stored values. A failed save does not
block startup: the language is used in memory and detection is retried on the next launch.
`get_language` supplies it before the frontend's first paint, and the tray and notifications
read the same value. Once saved, later launches use the tag without querying the operating
system again. A manual choice in settings replaces that saved tag.
An unknown nonblank tag already in the file retains the existing `en-US` fallback behavior
and leaves the file unchanged.

## Frontend

`src/i18n/` holds the setup, the language list and one JSON file per tag under
`src/i18n/locales/`. Keys are grouped by feature — `app.*` for the shell, `nav.*` for the page
headings, `events.*` for the event bus, plus a group per feature (`todo.*`, `pomodoro.*`,
`settings.*`) as its page lands — so a missing translation is visible from the key itself;
`config.ts` holds the default tag, the languages on offer and the reserved `ja-JP`, whose file
stays a stub until T30. `main.tsx` resolves the stored language before the first paint,
`useI18n.ts` hands a component its translator plus the switching action, `LanguageSwitcher.tsx`
renders the choice, and `I18nProvider.tsx` mounts the i18next instance around `App.tsx`.

Shared numeric controls take translated button names as props. Settings use
`numericInput.increase` / `numericInput.decrease`, interpolating the translated field label
so each arrow has a distinct accessible name (T34).

The choice lives in `config.json` (T05) and is read and written through `get_language` /
`set_language` (`commands/settings_commands.rs`). The settings page adds the remaining
entries (T16) and `ja-JP` becomes selectable once T30 fills its file; while the backend is
unreachable — a plain `pnpm dev` in a browser — the interface still switches for the
session.

Task layout copy lives under `todo.display.*` (setting name, choices, descriptions and save
errors), `todo.section.*` (one-time and recurring section headings) and `todo.type.*` (merged
row type badges). Both locales provide the same keys.
Task recurrence copy lives under `todo.recurrence.*`: presets, custom interval units, schedule
badges and the next-cycle label. Summary keys use i18next plural forms (`*_one`, `*_other`);
next-cycle dates are formatted with `Intl.DateTimeFormat` in the selected language.
The todo due-date controls use `todo.dueDate`, `todo.dueOn`, `todo.setDueDate`, `todo.date.*`,
`todo.save` and `todo.cancel` in both offered locales. Native year/month/day dropdown labels,
clear and today/tomorrow shortcuts are translated; month names and the list date use
`Intl.DateTimeFormat` with the active locale and UTC to preserve the selected calendar date.
Sidebar settings use `sidebar.*` for the section, visibility labels, move buttons, reset action
and save failure feedback. Panel names reuse `nav.*`, including the accessible button labels;
both supported locales carry the same keys.
Typography copy lives in `font.*`, including the family groups, size range, loading/save errors,
and numeric arrow labels. The reusable `NumericInput` receives its accessible labels from the
caller. Installed family names and the JetBrains Mono brand name are shown as supplied by the
font vendor; they are not translation keys.

## Backend

Commands return an error code rather than a translated sentence: the frontend switches on
the code, while the backend `message` is fallback copy for logs and for codes the frontend
does not know yet (see `docs/commands.md`). `services/i18n.rs` supplies that fallback:

- `Language::code()` / `Language::from_code()` convert between the enum and the BCP-47 tag
  (`"zh-CN"`, `"en-US"`); an unknown tag is `None`.
- `Config` in `config.rs` reads and rewrites the `language` field of `config.json`, resolving
  saved tags with `Language::from_code()`. A missing choice is detected as described above;
  unsupported tags fall back to `Language::DEFAULT` (T05).
- `ApiCode::message_in(language)` is the code → copy table. Its `en-US` arm delegates to
  `ApiCode::default_message()` in `utils/response.rs`, so English copy stays in one place.
- `ApiError::localized(language)` replaces the message only while it is still the English
  default, leaving a context-carrying message alone:

```rust
let generic = ApiError::new(ApiCode::Io).localized(Language::ZhCn);
assert_eq!(generic.message(), "输入输出错误");

let specific = ApiError::invalid_input("title must not be empty").localized(Language::ZhCn);
assert_eq!(specific.message(), "title must not be empty");
```

`details` is never localized: it is a diagnostic for logs and bug reports.

| Code | `en-US` | `zh-CN` |
| --- | --- | --- |
| `OK` | OK | 成功 |
| `INVALID_INPUT` | Invalid input | 输入无效 |
| `NOT_FOUND` | Record not found | 记录不存在 |
| `CONFLICT` | Conflicting state | 状态冲突 |
| `DATABASE` | Database error | 数据库错误 |
| `IO` | I/O error | 输入输出错误 |
| `PERMISSION_DENIED` | Operation denied by the system | 系统拒绝了该操作 |
| `UNSUPPORTED` | Not supported yet | 暂不支持 |
| `INTERNAL` | Internal error | 内部错误 |

## Adding a language

1. Add the variant to `Language` and `Language::ALL`, plus its tag in `code()` and
   `from_code()` and its system-locale mapping in `from_locale()` in `services/i18n.rs`.
2. Add the `message_in` arm for every code — the test that walks `Language::ALL` against
   `CODES` fails until each pair has copy.
3. Add `src/i18n/locales/<tag>.json` (T07) and the option in the settings page (T16).
4. Add a row to the language table above.

## Rules

1. A new user-visible string lands in both locale JSON files in the same commit
   (`CONTRIBUTING.md`, definition of done).
2. A new error code means: `ApiCode`, the `ApiCode` union in `src/types/index.ts`, a row in
   the `docs/commands.md` error table, one `message_in` arm per language, and the table
   above.
3. Copy belongs in the locale files and the tables above, not in code comments.

Date sorting is global within each task-type section: both directions put undated tasks last, with newest id first for ties, regardless of completion. Default ordering keeps active tasks first. Overdue means an unfinished deadline before the user’s current local calendar day; a task due today is not overdue.

The sidebar settings entry opens a modal drag editor. Pointer and keyboard reordering animate smoothly, visibility changes apply immediately, and closing the editor restores focus to its Edit button.
